# Agent Skill 真实评测与成本取舍

2026-10-12，模型 `DMXAPI-deepseek-v4-flash`。完成 **48 次真实模型调用、114,046 个供应商返回 Token**，保留失败；另做 32 份冻结产物的浏览器复验，复验没有模型费用。

## 指标

| 方案 | 实时一次修复通过 | 输入 Token | 输出 Token | 总 Token |
|---|---:|---:|---:|---:|
| 原流程：关闭 Skill、整页修复 | 14/16（87.5%） | 21,198 | 13,688 | 34,886 |
| 初版 Skill v1.0：指导与整页修复 | 13/16（81.25%） | 29,272 | 18,074 | 47,346 |
| Skill v1.1：精简上下文与局部补丁 | 13/16（81.25%） | 28,832 | 2,982 | 31,814 |

- **Skill 迭代收益**：总 Token 从 47,346 降至 31,814，减少 **32.81%**；总体通过率同为 81.25%，但两版失败案例分布不同。
- **相对原流程**：总 Token 减少 **8.81%**，输出 Token 减少 **78.21%**；通过率从 87.5% 降至 81.25%，不能宣称质量提升。
- Token 是供应商 usage，不是按字符估算。未配置实际价格，不能换算为费用降幅。没有使用别人的基准成绩。
- 由于质量取舍，Skill **默认关闭、由用户显式启用**；已有任务恢复时沿用其原开关和技能版本。

## 对照设计

固定 8 个失败页面：2 个历史失败产物、6 个新编写的开发探针。每个案例每方案重复两次，单编码角色用于隔离修复策略；不是三角色协作收益评测。

两组使用相同需求、原始 HTML、冻结验收契约、temperature=0.2、最多一次模型修复、每次 50000 Token 保守预算。初始失败 HTML 由评测适配器注入，不调用生成模型；只有修复是真实调用。因此指标是**给定失败页面的一次修复通过率**，不是从需求开始生成应用的成功率。

首轮 32 次调用在关闭 Skill 与 v1.0 间交替顺序。发现初版没有收益后，新增结构化 old/new 替换工具并精简上下文。第二轮新增 16 次 v1.1 调用，完整复用前轮全部 16 条基线，包括失败。逐例核对关闭 Skill 的提示、输入、输出 schema 与预算完全一致。

第二轮是**非同期开发对照**。案例用于诊断和迭代，不能称独立测试集或泛化基准；同一案例重复运行也不能当作两个独立需求。改进同时包含提示、上下文和工具，不能只归因于 SKILL.md 文件。

## 失败及确定性工具复验

- S02 的两次基线和各技能版本仍未通过：目标结果区包含装饰标签，未达到精确文本断言。保留失败，未删改测试。
- v1.0 在 S07 一次整页改写中引入 JavaScript 语法错误。
- v1.1 的 S01 第二次回复包含一个 old=new 的中性条目和四个有效编辑，早期应用器拒绝整份回复。修正为跳过唯一匹配的中性条目，仍拒绝无有效编辑、非唯一锚点和重叠。
- 对全部 32 份基线/改进组冻结输出执行原浏览器契约：基线仍为 14/16，技能仍为 13/16。S01 的有效补丁能够应用，但页面交互仍失败。因此**没有把工具错误消失算作业务成功**。
- 最终中性条目修正只做了离线真实输出复验，没有追加付费调用，不冒充新一轮实时模型测试。
