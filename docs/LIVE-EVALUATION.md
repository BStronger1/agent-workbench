# 真实模型测试

目前公开的结果为 25 项后端测试、浏览器流程测试和 36 项确定性演示验收。2026-10-06 核查时，工作台未配置服务端 Key，也没有个人模型配置文件，未发现真实模型运行记录。真实评测前置检查因未启用模型而停止，没有调用模型。

## 小规模测试入口

在 `qa` 目录执行：

```bash
node live-smoke.mjs --live
```

需要先提供以下三种配置之一：

- 为这个命令进程设置 `EVAL_BASE_URL`、`EVAL_MODEL`、`EVAL_API_KEY`。脚本创建隔离的临时浏览器空间，结束后清除该空间的模型配置，不修改其他空间。
- 设置 `EVAL_STORAGE_STATE`，指向已配置个人模型的 Playwright 会话文件。该文件包含空间访问凭据，只能保存在私有、排除版本控制的目录；此模式不改动原模型配置。
- 使用部署者配置的共享 live 模型，并通过 `LIVE_ACCESS_TOKEN` 提供调用口令。

新建的评测空间不会自动继承普通浏览器里的模型配置。不要将 Key 写进命令行历史、Git 文件或报告。`BASE_URL` 指定工作台地址；私有 CA 的 HTTPS 连接需设置 `NODE_EXTRA_CA_CERTS` 为受信任的公开 CA PEM 文件路径。

## 测试范围和预算

- 选取开发集的 3 个场景，各执行无记忆与检索记忆两种配置，共 6 个任务。每个任务使用独立项目，避免前序运行历史干扰。
- 每任务最多修复 1 次，最多 12 次生成请求；每次请求最多输出 4096 Token，每任务保守预算为 24000 Token。实际账单以服务商为准。
- 不注入演示故障；只在真实产物未通过校验时触发修复。若所有任务首轮通过，只能报告生成通过，不能声称验证了真实模型修复能力。
- 记录首次通过、最终通过、修复尝试与成功数量、耗时、供应商 Token，以及每次产物和验收反馈。供应商未返回用量时保留未知，不估算为零。
- 运行结果逐项写入 `evidence/live-smoke.json`。中断会保留已完成结果及待完成运行 ID；超时不自动重试，以免重复付费。
- 这是小规模开发场景验证，不是独立测试集成绩，也不能据此证明记忆检索提升效果。两种配置用于核对上下文接线和端到端运行，后续需独立的记忆约束评分和重复实验。

报告只在确认工作台处于 live 模式后创建。没有配置、连接失败或格式错误时应保留失败状态，不能以演示截图、连接测试成功或 Mock 响应替代真实生成验证。
